# 4DX Scoreboard — Корпоративный Бот + Mini App

## Описание проекта

Система отчетности и визуализации целей компании в Telegram.

**Две части:**
- **Telegram Бот** — сбор данных, напоминания, администрирование
- **Telegram Mini App** — визуализация прогресса (Табло) с историчностью

**Методика:** Еженедельное отслеживание «Опережающих показателей» (усилия за неделю) и «КВЦ» (глобальная цель).

---

## Роли и Доступ

Система закрытая. Белый список пользователей.

### 2.1. Супер-Админ (COO)
- **Идентификация:** По Telegram ID (хардкод или первый запуск по паролю)
- **Функции:**
  - Ввод данных по Главной цели (Сумма выручки/$)
  - Получение списка «Должников» (кто не сдал отчет)
  - Доступ к Админ-панели для настройки целей

### 2.2. Руководители отделов (8 человек)
- **Идентификация:** По Username (заранее прописаны в конфиге)
- **Привязка:** Каждый username жестко привязан к своему Отделу
- **Функции:**
  - Получение напоминаний
  - Ввод двух цифр еженедельно (План на неделю / Прогресс КВЦ)
  - Корректировка ошибочно введенных данных

### 2.3. Сотрудники (Наблюдатели)
- **Идентификация:** Подают заявку в боте → Админ одобряет
- **Функции:** Только просмотр Табло

## Функционал: Сбор данных (Бот)

### 3.1. Сценарий «Пятничный отчет»

**Триггер:** Пятница (время настраивается, например 14:00)

**Рассылка:** Бот пишет Руководителям: «Время отчета за неделю [Даты]»

**Диалог ввода:**
1. «Сколько [Название опережающего показателя] выполнено за эту неделю? (План: X)» → [Число]
2. «Какой общий прогресс по КВЦ [Название цели]? (Цель: Y)» → [Число]

**Обработка:** Бот сохраняет данные с привязкой к номеру недели и текущей дате.

### 3.2. Система «Напоминаний» (Nagging mode)

- Если данные не введены до 17:00 (пятница) → бот пишет каждый час: «Ждем отчет!»
- Если не введены до конца дня → Бот отправляет Админу сводку: «Не сдали отчет: Отдел 1, Отдел 3...»

### 3.3. Корректировка

- Кнопка в меню: «Исправить отчет за эту неделю»
- Логика: Запускает диалог заново, перезаписывает данные текущей недели

## Визуализация: Табло (Mini App)

**Главное требование UI:** На всех графиках видна динамика относительно прошлой недели. Видно «Рывок».

### Блок 1: ГЛАВНАЯ ЦЕЛЬ (Header)

- Заголовок: «Цель: $1 000 000»
- График: Горизонтальная шкала (Progress Bar)
  - Слой 1 (Яркий): Текущая сумма
  - Слой 2 (Бледный): Сумма прошлой пятницы
- Текст: Крупно текущая сумма и %, мелко «Прошлая неделя: $XXX (XX%)»

### Блок 2: ЛЕНТА ОТДЕЛОВ (8 карточек)

Каждая карточка:

**А) Заголовок:** Название отдела

**Б) Шкала 1: Опережающий показатель (Недельный план)**
- Суть: Сделали ли норму на этой неделе?
- Визуал: Шкала от 0 до Плана
  - Слой 1 (Яркий): Факт этой недели
  - Слой 2 (Бледный): Факт прошлой недели
- Текст: «7 / 10 (Прошлая нед: 8)»

**В) Шкала 2: КВЦ Отдела (Глобальная цель)**
- Суть: Насколько приблизились к финишу
- Визуал: Накопительная шкала от 0 до Финала
  - Слой 1 (Яркий): Текущий накопленный итог
  - Слой 2 (Бледный): Итог на прошлую пятницу
- Эффект: Видно какой кусочек «закрасился» за эту неделю

## Админ-панель

Гибкое изменение настроек без программиста.

**Для каждого отдела:**
- Изменить Название КВЦ (текст)
- Изменить Финальную цель КВЦ (цифра)
- Изменить Дедлайн (дата)
- Изменить Название Опережающего показателя (текст)
- Изменить Недельный План (цифра)

**Управление персоналом:**
- Назначить username руководителя для отдела

## Технические требования

### Историчность данных (Snapshots)
- **ЗАПРЕЩЕНО:** UPDATE (перезапись)
- **ОБЯЗАТЕЛЬНО:** INSERT (новая запись для каждой недели)
- Структура: `Get(Week_Current)` и `Get(Week_Current - 1)`

### Обработка «Нулевой недели»
- Если данных за прошлую неделю нет → бледная шкала = 0

### Стек
- **Язык:** Python (Aiogram)
- **Frontend:** HTML/JS (SPA)
- **База данных:** SQLite (с timestamps)
